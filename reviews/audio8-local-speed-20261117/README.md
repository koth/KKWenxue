# Audio8 本机原生推理提速

2026-11-17，Windows / RTX 3080 10GB / CUDA 12.4 / PyTorch 2.5.1+cu124。按用户要求在本机完成实现、原生编译与真实模型测试；Jetson 服务保持原运行版本。

本轮有效结果为 **1.66 倍吞吐、耗时减少 39.7%**，尚未达到两倍。保留 BF16、完整 2048 注意力长度、原模型/codec/cwns 音色和采样设置。开启参数为 `--fused-kernels`，运行时版本为 `fused-decode-v6`；省略该参数即可使用原路径。

## 配对基准

同机串行执行旧二进制和新二进制，三段正文各预热一次，然后各测三轮。每次请求记录完整生成、codec、文件保存和外部 wall time；启动和前三次预热不进入热机汇总。没有通过缩短音频、改变成品倍速或减少生成帧数计算提速。

| 指标 | 原版 expanded-kv-v3 | fused-decode-v6 |
|---|---:|---:|
| 热机请求数 | 9 | 9 |
| 对应音频 | 55.310 s | 55.310 s |
| 热机总耗时 | 15.295 s | 9.217 s |
| 生成 1 秒音频耗时 | 0.2765 s | 0.1666 s |
| CUDA 分配器峰值预留 | 3646 MiB | 3626 MiB |

[旧版原始记录](baseline.json)、[新版原始记录](optimized.json)、[完整输出比较](comparison.json)。全部 12 对输出（含三次预热）的 NPY 编码和 WAV/PCM 哈希一致。内存数字来自分配器，不是系统总内存或整机显存占用。

该基准是三个固定短样本的热机结果，不等同于整章、整本书或 Jetson 速度。更早一组仅预热首个样本的测量也得到约 1.66 倍；完整预热复测覆盖了各样本的 codec 形状。

## 实现

- 用原生 CUDA 合并逐帧 RMSNorm、RoPE、SwiGLU 和 QKV 缓存写入。保留激活、旋转结果及归一化乘权重前的 BF16 舍入；禁止编译器将乘加合并而改变 RoPE 的计算顺序。
- 单帧前馈 gate/up 投影合为一次矩阵运算；预填充仍使用原来的两个形状。原权重改为组合存储的视图，避免常驻两份大矩阵。
- 慢模型缓存 math SDPA 实际使用的已缩放 FP32 K，每帧只计算新增位置。解码保留原来的 Q/K 分别缩放顺序和完整注意力宽度；预填充恢复原 BF16 K。
- 语义采样使用独立 CUDA Graph，保留 top-k/top-p、温度、重复抑制与随机数消费顺序。参数改变时重新捕获，种子改变时复用图。
- 修复 Windows 构建脚本的仓库根目录定位，支持显式指定 LibTorch、CUDA 架构和 MSVC 工具集。基准及相关验证脚本显式使用 UTF-8。

## 验证

- [原生算子检查](kernel-check.json)：BF16、FP16 的归一化、RoPE、SwiGLU、展开 KV，以及 0/2047 缓存位置的缩放键检查通过；400 行随机 RMSNorm 对照与其余检查输出一致。
- [真实模型数值检查](numerics.json)：投影及展开/缩放缓存的预填充隐藏状态与 logits 一致。前缀拆开预填充相对整段预填充仍有既有 BF16 舍入差异，单独记录，不声称二者逐元素等价。
- [采样图检查](sampling-graphs.json)：五次请求、六个片段，覆盖种子切换、温度/top-k/top-p 改变后重建、图复用、切回原配置和连续两句生成；全部编码与 PCM 与旧二进制相同，两边均捕获三次。
- [缓存检查](voice-cache.json)：十项通过，覆盖缓存命中、参考路径切换、同路径逐字稿修改和编码修改。替代参考是独立的 cwns 元数据测试夹具，用于缓存失效验证，不是第二个真实音色的听感验收。
- [内容识别](asr.json)：CPU Whisper small 对三段最终基准读到句末，专名、代词和停顿存在识别差异。ASR 不证明逐字准确；本轮未改变输出的证据是完整编码和 PCM 配对比较。
- 原生分句测试六组边界通过。构建、算子检查、真实模型与采样图检查均在本机运行。

## 未采用的实验

短序列注意力尝试完全融合为一个 CUDA kernel。扩大随机探针后发现一处 BF16 差异，完整生成也发生变化，已从最终实现移除。没有用它的较快数字作为有效结果。

原版本身在较长样本上出现提前结束，最低时长检查未覆盖所有漏读；相关样本从正文内容基准中移除。最终三段样本另做识别检查，再进行相同文本和种子的配对测量。本轮没有修复所有长句生成问题，也没有把漏读算作提速。

## 复现

本机二进制为 `audio8-cpp/build/Release/audio8-tts.exe`，旧版隔离副本为 `tmp/audio8-baseline/audio8-tts.exe`。模型为 `tmp/audio8-model`，固定上游版本 `6bf7a980759d8022a66922ee975dab99229a2dd9`；默认声音为用户提供的 cwns.mp3 离线编码。

先按 [构建和运行说明](../../audio8-cpp/README.md)设置 DLL 路径，再用 `audio8-cpp/benchmark.py` 分别运行旧版和新版；新版加 `--flag=--fused-kernels`。使用 `tests/compare_runs.py` 比较完整输出。算子检查目标为 `audio8-kernel-check`，采样图验证入口为 `tests/validate_fused_graphs.py`。本次完整 WAV/NPY 保留在忽略目录 `tmp/audio8-runs/baseline-warm` 和 `tmp/audio8-runs/optimized-warm`。

`--fused-kernels` 目前需显式开启；本轮测试支持的是这里记录的 BF16 本机配置，未宣称新路径已经在 Jetson 上验收或部署。
