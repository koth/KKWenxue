# Audio8 参考上下文缓存与生成优化

目标设备：Jetson Orin Nano 8GB，保持 15W 模式；默认 cwns.mp3、原采样参数与 1.0 倍成品速度。正式候选为 `compact-prefix-v2`。

## 改动

- 模型和 codec 原本就是常驻进程，录音编码原本也有磁盘缓存；此次消除每段的重复文件哈希、NPY 读取、GPU 参考张量传输、参考文稿分词和参考前缀预填充。
- Python 校验缓存最多 8 个音色，设备、inode、大小、mtime 与 ctime 变化后重新校验内容哈希。原生进程最多保留一个 GPU 音色前缀及各层 KV 快照，切换音色或参考文件变化后重建。
- 从 155,776 项输出词表中只计算 4096 个语义 token 与 EOS，压缩投影、排序与采样；保留原注意力数值路径。新增 `inference_revision` 区分新旧任务缓存。
- 记录命中状态、参考准备、文本预填充、逐帧生成与解码时间。较长中文音频明显过短时拒绝发布，走已有重试和拆分流程；时长检查不能证明逐字完整。

## 配对基准

在同一设备上串行运行同样的三段正文、cwns 音色及种子，各进程首个预热请求不计入热机指标。完整记录见 [原版](baseline.json)、[优化版](optimized.json) 和 [脚本](benchmark.py)。

| 指标 | 原版 | compact-prefix-v2 |
|---|---:|---:|
| 三段累计耗时 | 81.38 s | 75.10 s |
| 对应原始音频 | 35.39 s | 34.97 s |
| 每秒音频耗时 | 2.300 s | 2.147 s |

实时率下降约 6.6%，同文总耗时下降约 7.7%。优化改变随机采样序列与 BF16 计算形状，输出音频并非逐样本相同，因此同时列出时长与实时率。不能把此短样本基准等同于整本书速度。

命中时参考准备实测约 0.09–0.14 ms，参考前缀预填充为 0；正文后缀预填充约 52–61 ms。主要耗时仍在逐帧自回归推理，单靠参考缓存不会带来倍数提升。

## 内容与数值边界

[稳定版内容识别](asr-v2.json) 覆盖短对白、98 字长句和普通叙述，未发现漏读或重复；专名与代词存在同音字差异。ASR 仅为内容检查，不能代替音色和韵律试听。

另外试验过 512/1024/2048 位置的注意力图，原始实时率可降至约 1.66，但出现长句提前结束。保留原 RNG 序列后仍有漏读，长组合段也未通过最低时长检查；该方案已撤回，未部署到正式服务。这些较快的数字不能作为有效提速结果。实验源与二进制保存在设备 `/home/jetson/workspace/audio8-speed-20261116/experimental-buckets/` 及同目录备份中。

参考前缀分开预填充会产生 BF16 舍入差异；数值检查记录实际误差并限制相对 RMSE、最大误差和概率分布偏差，不宣称黄金编码一致。历史逐编码对照保留 `--full-vocab --no-prefix-cache` 模式。
