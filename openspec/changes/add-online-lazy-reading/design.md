## Context

当前 App 启动时将内置书和本地 SQLite 合并到 `Library.books`，在线书籍通过 `CatalogClient.startContent` 获取整本 ZIP。catalog 只保存书籍元数据，content worker 通过 `/txt/?id=...&p=...` 下载整本文本并切分；App 的 `Book` 直接持有每个 `Chapter.body`，因此大书导入和内存占用都与全书规模绑定。

源站详情页包含完整目录项，每项可以映射到 `/bookId/articleId.html` 章节页。catalog 已经具备访问源站的网络位置和 relay 服务凭据，能够在服务端完成章节页代理、清洗、缓存和哈希校验。

## Goals / Non-Goals

**Goals:**

- 首次安装为空书架，只能通过在线 catalog 加入阅读书籍。
- 用户先看到书名、作者、章节目录和远程版本，再按章获取正文。
- 当前章节加载优先，下一章和下下章后台预取；前台阅读不等待整本下载。
- 进程重启、断网、取消和失败后恢复目录、正文缓存和后台队列。
- 版本更新只处理章节差异；显式全书缓存不影响正常阅读。

**Non-Goals:**

- 首版不做账号系统、跨设备阅读进度同步或云端书架同步。
- 不允许 App 直接访问源站，不把 relay token 放入 APK。
- 不把整本 TXT 继续作为交互导入的默认协议；整本 ZIP 只用于显式缓存/导出。
- 不在本变更中实现推荐、订阅、付费或多源书库聚合。

## Decisions

### 1. 目录与正文分离

新增服务端概念：

```text
online_books
  书籍身份、书名、作者、remote_revision、chapter_count

online_chapters
  book_id、chapter_id、ordinal、title、source_article_id、body_sha256

chapter_cache
  book_id、chapter_id、remote_revision、normalized_body、bytes、sha256、state、updated_at
```

App 保留 `Book`/`Chapter` 作为现有阅读器接口，在线数据库只保存章节引用和可选正文哈希，正文列为空。`OnlineChapterStore` 独立管理文件和校验元数据；阅读页只在内存保留当前位置前后两章的正文，不把正文写回整本数据库。测试书籍只放在测试源码中。

### 2. 目录优先导入

`GET /v1/catalog/books/{id}/manifest` 返回书籍元数据、manifest revision、章节总数和分页章节引用。实现选择先完整验证轻量目录快照，再一次事务发布到书架，避免部分目录被当作整本、重复分页或目录中途变化造成缺章。每页最多 500 条，后续页携带首个响应的 revision，最多 10 万条；首次导入不请求正文、整本任务或 ZIP。阅读器目录使用虚拟列表显示本地引用。

服务端从源站详情页及后续目录页提取章节标题和源站文章 ID。缺失目录可按用户请求即时补齐，另有运维后台回填；完整抓取并验证后才发布。目录失败或源站改版时返回明确的 `manifest_unavailable`，不伪造章节编号；已存在的旧 manifest 仍可离线显示。

### 3. 单章正文代理

`GET /v1/catalog/books/{bookId}/chapters/{chapterId}` 由 catalog 校验章节属于该书，再请求源站章节页面，提取正文、移除广告和导航、使用阅读器一致的段落规范化规则，计算正文 SHA-256，并返回：

```json
{
  "bookId": 7407,
  "chapterId": "online:catalog:7407:chapter:source:4888516",
  "revision": "catalog-v2:7407:...",
  "title": "第338章 ...",
  "body": "...",
  "sha256": "...",
  "bytes": 12345
}
```

catalog 对相同 `(book_id, chapter_id, revision)` 使用可取消的互斥 single-flight，避免多个 App 请求同时抓源站。只跟随同一章的“下一页”，不跟随下一章；最多 50 页，正文最多 2 MB。响应支持 ETag/If-None-Match；源站失败返回可重试的错误，不把 relay 或源站路径泄露给 App。内存缓存上限 64 MB，SQLite 正文缓存上限 256 MB，正文新鲜度为 6 小时；首次取得哈希不改变 manifest revision，已知正文哈希变化才推进版本。

### 4. App 阅读与预取

阅读器打开章节时按以下顺序取正文：内存缓存 → 本地正文缓存 → 网络请求。当前章网络请求使用前台优先级；请求期间页面保留目录、标题和阅读器骨架，不显示全书导入进度。正文成功后才创建排版对象、阅读锚点和听书输入。

持久后台队列使用 WorkManager 或等价的持久调度器：

- 当前章节：优先级 100，立即执行。
- 下一章、下下章：优先级 70，自动预取。
- 上一章：优先级 40。
- 用户选择的章节范围：优先级 30。
- 全书缓存：优先级 10，可暂停、恢复和限制并发。

每本书最多一个活动 manifest 刷新。正文任务的章节 ID、独立状态和重试时间保存在 SQLite 中，各书共用一个 WorkManager 后台调度器；相邻、范围和全书任务分开保存，翻章不会覆盖全书任务。网络并发上限 2，后台最多占 1 个槽位，另一个留给当前章节。失败章节最多自动尝试 3 次，按指数退避；正常批次完成后立即接续，不因章节多而累计退避。暂停保留成功检查点；进程重启恢复待办章节。

App 自动正文缓存目标上限 512 MB，按最近使用清理；当前写入、书签及用户明确缓存的章节受保护，保护内容可以超过自动缓存目标。书签保护与显式缓存保护分别记录。缓存文件原子落盘并校验长度、哈希和章节身份；损坏缓存只重取该章。

### 5. 在线更新

App 先请求远程 manifest revision，再比较章节引用和 `body_sha256`。新增章节写入本地索引并标记未缓存；标题或正文哈希变化的章节标记 stale 并删除旧正文缓存；删除或重排只更新索引和阅读位置映射。当前正在阅读的旧正文可以继续显示，下一次进入时按新 revision 加载。

不再通过整本更新 ZIP 自动更新在线阅读书籍。“缓存全书”和“缓存范围”按章节加入上述低优先级队列，提供进度、暂停、继续和可滚动的失败章节清单。“准备整本导出”另外创建 `/bundle` TXT/ZIP 任务，由既有 content worker 和 relay 生成包含 `book.txt` 的包；App 保存任务 ID 与临时文件，支持 Range/If-Range 续传，校验完整大小和 SHA-256 后才允许通过系统文件选择器保存 ZIP。导出与交互章节请求分开执行。

阅读锚点以稳定章节 ID、正文哈希和短原文上下文保存。目录重排先按 ID 恢复；异步正文到达后再次定位上下文，原句删除或匹配不唯一时要求用户重新定位，不能把未加载正文当成空文本而把进度归零。

### 6. 空书架和来源约束

`Library` 初始集合为空，`BookDatabase` 不复制 asset 种子库。书架的唯一添加入口是在线 catalog 导入；TXT/EPUB 选择器和本地书籍导入按钮删除。首页、书架、听书和合成页都必须处理没有任何书的状态，不能调用 `Library.books.first()` 或用默认书籍兜底。

音频听书包仍作为音频资源导入能力单独存在；它必须关联已经存在的在线书籍和章节引用，不能借此创建离线阅读书籍。

## API

| 接口 | 作用 |
| --- | --- |
| `GET /v1/catalog/books/{id}/manifest?cursor=&limit=` | 分页返回书籍元数据、manifest revision 和章节引用 |
| `GET /v1/catalog/books/{id}/chapters/{chapterId}` | 返回单章规范正文，支持 ETag |
| `POST /v1/catalog/books/{id}/prefetch` | 创建或复用后台章节预取任务，提交章节 ID 列表和优先级 |
| `GET /v1/catalog/prefetch/{taskId}` | 查询预取任务进度、失败章节和可重试项 |
| `POST /v1/catalog/prefetch/{taskId}/retry` | 只重试服务端任务中的失败章节 |
| `POST /v1/catalog/books/{id}/bundle` | 用户显式请求整本离线缓存/导出包 |

## Failure and Recovery

- manifest 请求失败：保留旧目录，显示目录过期并提供重试。
- 当前章请求失败：显示章节级重试；不阻塞其他已缓存章节。
- 预取失败：记录章节级错误，按退避重试；不回滚已成功缓存章节。
- 正文校验失败：删除临时缓存，重新请求；超过预算后只标记该章失败。
- App 被杀或重启：从本地队列和缓存状态恢复，不重新下载已校验正文。
- 远程版本变化：以新 manifest 为准，旧正文保留到确认新版本成功后再按缓存策略清理。

## Acceptance Targets

- 首次在线导入只获取 manifest，不下载整本正文；1 秒目录、1.5 秒正文为网络良好时的优化目标，不作为任意公网环境的耗时承诺。发布验收记录实际链路耗时及目录大小。
- 打开未缓存章节时只等待当前章节，正文源站分页全部校验后显示，不能为了首屏速度截断同一章。
- 下一章预取不阻塞当前章节排版，前台请求优先于后台批量任务。
- 1000 章以上的书不把全部正文加载到内存或单次 SQLite 事务。
- 断网时已缓存章节可读，未缓存章节显示离线提示和重试入口。
