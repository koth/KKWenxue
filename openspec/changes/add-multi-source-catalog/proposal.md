## Why

当前目录服务把站点分配的数字 ID 直接作为书籍主键。`suduguu.com/203` 和 `sudugu520.com/407` 可能指向同一本书，也可能出现不同书源使用相同数字 ID 的情况。单一数字主键会导致新源无法安全接入，源站切换时还可能把目录、正文和更新状态写到错误的书上。

需要把书籍的产品身份与源站身份拆开。一本书拥有一个稳定的内部 ID，同时可以绑定多个来源。每个来源保存自己的外站书籍 ID、章节 ID、更新时间、可用状态和同步游标。作者和书名用于发现候选和消歧，不能在存在歧义时自动合并。

## What Changes

- 新增稳定的内部书籍 ID，作为目录、章节、正文缓存、版本和 App 书架关联的唯一书籍身份。
- 新增来源注册表和书籍来源绑定表，使用 `(source_key, external_book_id)` 唯一标识外站书籍。
- 为每个来源实现独立的抓取配置、解析器、健康状态、同步游标和错误记录。
- 将作者、书名规范化为可比较字段，建立候选匹配和人工确认状态，避免仅凭数字 ID 或模糊标题合并书籍。
- 将章节的内部身份与来源章节身份分开，支持同一本书在不同来源上的章节 ID 不一致。
- 调整目录 API，使 App 使用内部书籍 ID，来源选择由服务端返回并可显式指定；保留旧数字接口的只读兼容窗口。
- 增加来源优先级、健康度和新鲜度策略。来源失效时可切换到已确认的备用来源，切换过程不改变内部书籍 ID。
- 增加跨来源同步、冲突审计、回滚和迁移验收，确保源站错误页面或错配结果不会覆盖现有目录。

## Capabilities

### New Capabilities

- `catalog-source-registry`：来源注册、解析器版本、来源健康和同步游标。
- `multi-source-book-identity`：内部书籍、来源绑定、作者/书名消歧和人工确认。
- `multi-source-chapter-identity`：内部章节、来源章节映射、章节匹配和内容版本隔离。
- `multi-source-catalog-api`：内部 ID API、来源列表、显式来源选择和兼容错误语义。

### Modified Capabilities

- `online-library-catalog`：搜索和导入返回内部书籍身份及来源摘要，不再把外站数字 ID 当作书籍身份。
- `online-chapter-reading`：正文请求通过内部书籍和来源章节映射定位源站页面。
- `online-library-sync`：版本检查、更新计划和刷新请求按来源执行，再汇总到内部书籍。

## Non-Goals

- 首版不做全文语义相似度或机器学习自动合并。
- 首版不把不同来源的正文拼接到同一个章节版本中。
- 首版不在 App 内直接访问源站，也不把来源解析器或来源凭据下发到 APK。
- 首版不自动把低置信度候选合并为同一本书。

## Success Criteria

- 同一本书在两个来源使用不同外站 ID 时，App 书架只有一个内部书籍条目，并能查看两个来源绑定。
- 两本书作者和书名相同但实际内容不同的时候，系统保留两个内部书籍，不静默合并。
- 旧目录数据库迁移后，既有书籍的内部 ID、阅读绑定和章节缓存仍可访问，旧外站 ID 只存在于来源绑定中。
- 某个来源返回 404、Google 重定向、解析为空或目录突变时，该来源进入错误状态，不能覆盖其他来源的可用目录。
