## Why

目前选章节、修改声音、试听、查看合成进度和下载音频都要手动操作服务器，难以管理长任务、失败片段和多个音频版本。需要把已有 TTS 脚本服务化，让本地 Web App 完成选书、选章节、设置声音、提交任务和获取音频的完整流程。

服务器已按用户要求停止合成并清空内容，模型和运行环境仍然保留；服务从空库启动。本地 Web 直接读取阅读器书库，仅在用户提交任务时向服务器发送选中章节，不自动恢复已删除内容。

## What Changes

- 增加服务器 API、持久任务队列及单个常驻 GPU worker，支持批量合成、优先试听、暂停继续、取消和失败重试。
- 增加本地 React Web App 与启动器，复用 SSH 隧道连接服务器，提供章节选择、参数设置、任务进度、原文同步播放和下载。
- 增加可版本化的音色/语气预设，提供当前模型支持的 9 种独立讲述音色及中文说明；默认使用福叔（Uncle_Fu）、克制自然的讲述风格、1.0 倍速、180ms 句间停顿，旧 Dylan 及用户预设继续保留。
- 将语音生成与成品导出配置分开：只改倍速时复用 FLAC；换音色或语气时生成独立版本。
- 保留与阅读器一致的 UTF-16 原文锚点、逐段音频、章节 M4A 和 JSON 时间索引；按章节 ID 区分跨书籍及同号章节。
- 本地启动器只读加载阅读器 SQLite，目录、检索、范围解析和原文预览均在本机完成；服务器保存用户提交的章节快照、任务与音频。显式管理员导入命令保留给测试及历史迁移。
- 支持上传短 M4A/WAV/MP3 参考音频及逐字稿，创建 Qwen3-TTS Base 克隆音色预设；提供只提取音色模式与模型就绪校验。
- 首版包括目录、试听、合成、任务控制、播放及下载。浏览器上传 TXT/EPUB、IndexTTS2/VoiceDesign、多人配音、多 GPU、Android 播放接入留待后续变更。

## Capabilities

### New Capabilities

- `tts-catalog`: 本地书库读取与选中章节快照、显式管理员导入、章节范围解析、稳定章节 ID、规范原文与 UTF-16 锚点。
- `tts-voice-presets`: 模型支持的音色、已确认的默认预设、语气指令和不可变配置版本，以及独立的生成与导出设置。
- `tts-synthesis-jobs`: 持久队列、幂等提交、单 GPU 常驻调度、试听优先、任务控制、断点恢复、逐段校验和失败重试。
- `tts-audio-artifacts`: 片段缓存、版本化章节导出、完整性校验、时间索引、按句定位、Range 播放与批量下载。
- `tts-local-workbench`: 本地控制台、复用 SSH 连接、同源代理、连接恢复、任务展示和运行状态。

### Modified Capabilities

无。项目此前未建立 OpenSpec 基线；既有脚本行为通过本次新增能力承接。

## Impact

- 重构 `tts/synthesize.py`、`tts/synthesize_cuda.py` 和启动脚本，提取可被 CLI 与 worker 共用的目录、推理、校验和导出模块。
- 新增 `server/`、`web/`、`local/`，分别提供 API/队列、React + TypeScript + Vite 界面、本地静态服务与 SSH 连接代理。
- 新增 SQLite 服务元数据、任务、事件、预设及产物索引；保持音频为独立文件，兼容现有 UTF-16 cue 格式。
- API 与 GPU worker 分进程、分依赖环境；沿用保留的 CUDA 模型和运行环境，不因安装 Web 依赖而升级 PyTorch。
- 新增 `/api/v1` 的目录、预设、试听、任务、产物与下载接口，以及本地启动和服务器进程维护配置。
- 原有 Android 阅读和本地数据无需迁移；已按 apply 指令部署独立服务；不重启旧合成任务，不上传整本本地小说。

背景方案见 [原始工作台提案](../../../docs/tts-service-proposal.md)。本变更的 specs、design 和 tasks 是后续实施依据；原提案关于“已有服务器音频和运行任务”的描述仅代表清理前状态。
