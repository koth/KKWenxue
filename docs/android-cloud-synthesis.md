# Android 云端合成与任务导入

Android 0.9.10（versionCode 30）的「听书 → 合成与导入」连接通用 Rust 任务中转服务。阅读器继续使用本地小说库，GPU 服务器主动领取选中章节并合成、打包，先发布完成通知和局域网地址；手机优先直连下载，无法直连时才申请中转上传。正式引擎为 ZONOS3-Mini C++ / GGML CUDA，默认林川克隆音色。App 下拉列表提供林川和 Haoran；旧预设已移除。

## 首次连接

进入「听书 → 合成与导入 → 服务器」，填写服务地址和中转接入凭据，或选择「导入连接配置文件」并打开提供的 JSON。App 会先验证服务与凭据，再保存设置。连接文件格式：

```json
{"schema_version":1,"endpoint":"http://120.48.49.190:17870","token":"private-relay-token"}
```

连接文件包含接入凭据，应私下保存，不放进 APK。手机使用 Android Keystore 的 AES-GCM 密钥加密存储凭据；连接设置和派发日志位于 `noBackupFilesDir`。此凭据只连接中转服务，GPU API 管理 token 不传到手机。局域网下载只向私有/本机/链路本地地址发送独立的单包访问凭据，不携带 relay 或 GPU 管理凭据；不跟随 HTTP 重定向。中转下载路径仍由 App 根据任务 ID 构建。

当前部署使用 `http://120.48.49.190:17870` 进行 IP 联调。需要公网 HTTPS 时，为中转服务配置域名与证书，然后在 App 及 GPU worker 中修改地址。App 同时支持 HTTP 与 HTTPS。

## 派发与收听

1. 「派发合成」中选择本机已有书籍。章号支持 `984`、`984,986-988`，每批 1–100 章。
2. 点「解析章节」查看匹配目录，按标题中的真实章号匹配，缺号或单章号重复会明确报错。只发送选中的章节。
3. 在音色下拉菜单中选择 `林川`（默认）或 `Haoran`。菜单显示音色名称，预设版本 ID 由 App 在后台提交。参考文件留在 GPU 主机，App 不上传或创建新克隆。旧固定音色入口已移除；已有旧音频仍可播放。成品语速可选 0.8×、0.9×、1.0×、1.1×、1.2×，默认 1.0×，并保留 180ms 额外停顿和统一音量。
4. 点「派发合成任务」。已提交后，退出 App 不影响服务器合成。
5. 本机派发的任务会在合成完成后自动下载、校验并导入，不需要留在合成页面。优先局域网直连；不可达时才自动申请中转上传，随后下载。列表与等待上传使用不含正文的轻量状态，重复请求共用同一中转包。「服务器任务」展示下载进度、等待上传和自动重试状态，支持加载更早任务和按完整任务 ID 查找。
6. 导入后返回听书即可播放，原文高亮、音色版本、进度、离线播放与后台媒体控制沿用原播放器。
7. 片段合成先容忍个别错字和小幅识别差异，严重异常才在片段内有限重试；成功部分沿用。内容校验耗尽本地预算后不自动重跑整轮，避免堵塞后续任务。最终失败时，「服务器任务」提供「重试失败片段」，使用原文本、音色及参数创建关联任务，完成后仍自动下载导入。网络断开导致重试派发状态未知时沿用原幂等键确认，不重复创建。

阅读页的「听书」入口按当前书籍与章节 ID 选择音频，不沿用别章会话。本章尚无音频时显示「本章暂无听书内容」，点「去合成本章」会预填该书与真实章号。进入其他章节的播放器时会暂停此前章节的播放。书房和系统媒体通知入口仍保留当前播放会话。

章节播完后，后台播放服务按小说目录自动续播紧邻的下一章，从该章开头播放；优先选择相同音色，缺少相同音色时采用下一章已选或最新的可用版本。播放器标题、进度和通知随章节更新，倍速与分钟定时的原截止时间保持不变，锁屏后仍可续播。「本章结束」定时会阻止续播。下一章尚无音频时停止并提示合成或导入，不跳过缺章；最后一章结束后停止。

此列表展示中转服务里的 `tts` 任务，包括其他客户端派发的任务。本机从新版 App 派发的任务默认自动导入；其他客户端或旧版 App 派发的历史任务不会批量下载，点击一次「下载并导入」即可交给相同后台流程。原 Web 工作台直接写入 GPU 队列的历史任务仍通过工作台手动打包导入，不会自动上传历史音频到公网。

## 可靠性与结果校验

- 派发前在同一事务中保存请求快照、独立幂等键及自动导入记录，并安排 WorkManager 后台任务。派发状态未知时会自动复用原请求核对，手动「核对派发」也沿用同一幂等键，不重复创建。
- 后台任务持久保存在设备上，系统回收进程或设备重启后可继续；重新打开 App 也会补排未完成记录。每个服务器的凭据分别加密保存，切换当前服务器不影响已派发任务。WorkManager 的输入只有本地记录键，不包含凭据和正文。
- 原文快照直接使用 `Chapter.text`，保存与阅读器一致的 UTF-8 SHA-256、revision 及 UTF-16 定位基准；服务端重新分句和构建片段。
- 下载按服务器结果的字节数、SHA-256 和最大 4GB 限制校验，失败不导入；再调用现有整包导入器检查原文、目录/音频哈希、cue 和媒体时长，整包通过后才入库。
- 局域网连接超时为 4 秒、读超时为 8 秒；传输不可用才降级。文件哈希不符或手机写入失败直接报错，不自动消耗公网流量。中转上传独立于合成租约，失败重试不触发重新合成，也不占住后续合成任务。后台等待中转以短任务分步查询，不占住长时间下载线程；服务器上传继续执行。
- 重复导入不会产生重复音频版本。空间不足、结果过期、本地缺书或正文版本不同会显示原因。
- 断网、超时、HTTP 408/425/429 和服务端错误会按 10、20、40、80、160、300 秒递增间隔自动重试，后续最多间隔 300 秒。网络和存储约束满足后由系统调度继续。后台单次执行有时间预算，超过预算保留进度并接续下一步。
- 已下载部分保留在私有目录；局域网和中转接口均支持 Range / If-Range 断点续传。服务器忽略 Range 时安全重头下载，不追加重复数据。校验失败删除损坏文件并有限重试；下载完成但导入前进程中断时可直接复用校验通过的整包。
- 同一任务下载加文件锁，音频导入串行并保持幂等。凭据无效、缺书、正文版本不符或结果过期会明确提示；处理后可点「重试自动导入」，保存正确凭据会恢复对应被阻塞的任务。
- 离开页面和切到后台不取消任务。Android 可能因省电或厂商限制延后调度；在系统设置中强行停止 App 后，后台工作要等下次启动才恢复。自动入库不会自行开始播放。
- GPU 临时 ZIP 和局域网访问凭据有效期默认 24 小时；按需上传成功后公网包从上传完成起保留 24 小时。已经导入手机的音频不受临时结果清理影响。

## 已部署服务

| 位置 | 服务 / 数据 |
| --- | --- |
| `120.48.49.190:17870` | Rust `shanye-task-relay`，systemd 系统服务 |
| `/opt/shanye-task-relay/shanye-task-relay` | 公网服务 Linux 二进制 |
| `/etc/shanye-task-relay.env` | 私有配置，0600 |
| `/var/lib/shanye-task-relay/relay.sqlite` | 任务持久库 |
| `/var/lib/shanye-task-relay/tmp/<task-id>/` | 临时结果，默认 24h |
| Jetson `192.168.3.33` | `shanye-tts-relay-worker` 用户服务 |
| `192.168.3.33:17871` | 局域网 ZIP 下载，只接受单个结果的访问凭据 |

GPU worker 配置为 `/home/jetson/workspace/shanye-tts-service/service.env`，`SHANYE_RELAY_DIRECT_URL=http://192.168.3.33:17871`，监听 `0.0.0.0:17871`。必须使用稳定的 `SHANYE_RELAY_WORKER_ID`，重启后才能领取自己先前发布结果的中转请求。独立的 `relay-results.sqlite` 位于 GPU 服务 state 目录，保存任务与 ZIP、访问凭据、哈希和有效期的对应关系。合成继续复用既有 GPU/CPU 服务。部署连接使用 OpenSSH ControlMaster，未重建模型或环境。
